Selected decision records

The decisions that shaped it

The useful part of a decision record is the trade-off, not its reference number. These five decisions kept the toolkit understandable as it grew.

01

Use files as the handoff contract

Problem
Passing everything through conversational context made state hard to inspect and awkward to resume.
Decision
Each skill writes a defined artifact and passes its reference to the next step.
Consequence
Workflows are easier to review and restart, at the cost of maintaining clear artifact schemas.
02

Keep core skills tool-independent

Problem
Optional integrations should not decide whether the core work can run.
Decision
Core skills operate on repository artifacts and degrade when an integration is absent.
Consequence
The same workflow can run locally, though connectors must translate to a common contract.
03

Isolate the connectors

Problem
Fetch, publish and notify code changes more often than the architecture work.
Decision
External tools sit behind small connector seams with contained writes.
Consequence
Integrations can change without rewriting the workflow, but each connector needs capability and path checks.
04

Draft before doing

Problem
A plausible-looking agent response is not enough authority to publish or pass a governance gate.
Decision
Show the exact outbound payload or verdict, then stop for approval.
Consequence
A person stays accountable and automation ends at a deliberate pause.
05

Keep policy visible

Problem
Organisation-specific thresholds can easily become hidden branches in the workflow.
Decision
Keep thresholds and destinations in constrained configuration blocks.
Consequence
Policy changes are easier to review, while configuration still needs validation and ownership.

What I took from it

Producing more material and documentation is easy

The challenge is making use of it. Using specialised agents and clear handoffs allows architects to stay in control. That is why intermediary files, validation checkpoints and human approval pauses are baked into the architecture rather than considered at the end.

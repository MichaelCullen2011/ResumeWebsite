# Domain Docs

This is a single-context repository.

Before exploring, read the root `CONTEXT.md` and any relevant ADRs under `docs/adr/`. If either is absent, proceed silently.

Use the glossary's canonical vocabulary in issues, specifications, hypotheses, tests, and implementation plans. Surface conflicts with existing ADRs explicitly rather than silently overriding them.

Domain documentation is created lazily through the domain-modeling workflow when terminology or durable architectural decisions are actually resolved.
